## Research catalog API (ungated Tier-1, public-repo data only)
`GET /api/bot/research/catalog` — query: `q`, repeatable-or-CSV facets `theme status verdict goal backend kind stuck`, `sort` (`id title theme status verdict priority lastActivity created`), `order` (`asc|desc`), `limit` (1..200, default 50), `offset`, `since` (ISO; drives "new since last visit"), `created_from`/`created_to` (`YYYY-MM-DD`).
Response: `present`, `readState` (`read|partial|unreadable`), `readErrors[]`, `total`, `matched`, `limit`, `offset`, `sort`, `order`, `facets{facet:{value:count}}` (a facet's counts ignore its own selection; the value `none` = null), `items[]`, `stayOnTop`, `generatedAt`, `roadmapAvailable`.
`stayOnTop`: `{since, sinceKnown, new:{count,items}|null, stuck:{count,items}, due:{count,items}, recentVerdicts[]}`. **`new` is `null` and `sinceKnown:false` on a first visit — render "first visit", not "0 new".** Keep last-seen per browser in localStorage (try/catch; must render without it) and send it as `since`.
Item: `id title summary whyItMatters kind cadence theme priority roadmap[{id,name,goal,goalName,status}] status(queued|due|dispatched|running|result|blocked|retired) fileStatus dueState(due|not_due|unknown) dueReason blockedReason stuck stuckReason rule{id,registeredAt,registeredBeforeRun,statistic,text}|null power{state,expectedN,minDetectableEffect}|null verdict readState resultNote metrics{scalars} resultCount resultSource("results_dir"|"e35_bracket"|null) corpus{path,corpus,rows,rowsAfterStamp,latestSweepAt,graded}|null dataUsed{workflow,harness,inputs,dataInputs,population,n,store} backend estMinutes createdAt lastDispatchedAt latestResultAt lastActivity links{unit,results[],run}`. Any field may be `null` → "—".
`GET /api/bot/research/catalog/{unit_id}` — `{present, id, unit, resultRows[] (≤20, newest first), resultRowsTruncated}`; `present:false` for an unknown id; 400 on a malformed id.
Columns: id · title · theme · roadmap goal/milestone · priority · status · verdict · n · last activity. Drawer: summary/question, why it matters, pre-registered rule, metrics, data used, backend + est. minutes, timestamps, links.
Live numbers 2026-10-13 (567 units): 456 result · 57 blocked · 37 dispatched · 7 queued · 4 due · 6 retired; 110 stuck. "Stuck" = blocked, or dispatched >6 h with no landed result row, or `grading.needs_review`; it does not distinguish a failed run from an unmerged result.

Result sources: a unit's result is either `research/results/<uid>/*.jsonl` or rows tagged for it in `docs/research/e35-bracket-corpus.jsonl` at/after its dispatch stamp (`resultSource` says which). `verdict: null` with `resultSource: "e35_bracket"` means "result landed, ungraded" — show that, not a blank.

## Follow-up (2026-10-14): Overview endpoint exists once PR #17956 is merged and deployed
`GET /api/bot/db/overview` — **session-gated** (bearer), cached 60 s. Query: `integrity=off|quick` (default `off`; `quick` runs `PRAGMA quick_check` and can be slow on the journal — expose it behind an explicit "check integrity" button, never on page load).
Response: `{present, generatedAt, dbs[], summary{tables, emptyTables, unknownRowCount, dbsUnreadable, dbsMissing}, notProvided[]}`.
`dbs[]`: `{db ("trade_journal"|"trainer_store"), file, present, readState ("read"|"missing"|"unreadable"), reason?, sizeBytes|null, walBytes|null, journalMode|null, integrity{state ("not_requested"|"ok"|"failed"|"error"|"not_checked"), result}, tables[]}`.
`tables[]`: `{name, db, rows|null, rowsState ("read"|"count_failed"), empty (true|false|null), columnCount, newestRowColumn|null, newestRowAt|null, newestRowState ("read"|"empty"|"no_timestamp_column"|"null_value"|"unparseable"|"error"), ageSeconds|null}`.
Rendering rules: `rows: null` → "—" (never 0); `present:false`/`readState:"missing"` → "database not on disk", not an empty list; `integrity.state:"not_requested"` → "not checked", never a green tick; `empty:true` → flag the table. `newestRowAt` is the timestamp of the newest **inserted** row (highest rowid), not a MAX. **Not provided**: 24 h/7 d growth and a stale verdict (`notProvided`) — do not fabricate either; show `ageSeconds` as the raw fact. Until the route is deployed it 404s: render "overview not available yet", and keep the research-queue half from the catalog API.
Wire the Overview to it; link each table row to the All-tables browser. Then give Trades / Signals / Order packages the **same facets + search + sortable columns + detail drawer as the Research catalog** (shapes: the existing gated `/api/bot/db/table/{name}` takes `limit/offset/order_by/order_dir/filter_col/filter_op/filter_val` and echoes `filter_state` — check it is `applied` before trusting `total`).
